# Storage and indexing

The release design uses **one local SQLite database** under Electron's `userData` for source identities, documents, source content required for intentional reindexing, N=1–7 word counts, active source flags and settings. No remote DB or service is planned.

`typenudge.sqlite3` lives in Electron `userData`, with its WAL sidecars. A main-coordinated **local worker thread** owns the only runtime SQLite connection, enables foreign keys/WAL and serializes operations. Schema migrations 1→2→3→4→5 are transactional; future schemas are refused. Schema 3 remembers explicitly selected canonical import paths without exposing them to renderer. Schema 4 widens N to 7, preserves all previous N=1–3 rows and adds `sources.index_max_n` coverage. Existing imported paths, notes, consent and source activation survive.

Schema 4 migrates independent `enabledN` selections to their maximum (e.g. `[1,3]` → `maxN=3`, implicitly enabling 1–3), then replaces that old key with `maxN`, `poolSize`, `previewWords` and `acceptWords`. New defaults are 3/10/3/2. Older contributions display N=4–7 pending; Sources → Reindex explicitly rebuilds from retained text with progress. An identical reimport can also upgrade an obsolete index. Learned personal notes upgrade on an explicit Save with learning on, even with unchanged text; unlearned notes are never bulk-learned.

Schema 5 adds `ngramScales=[1,1,1,1,1,1,1]` transactionally to existing schema-4 settings without rewriting N-grams, source metadata, notes or consent. These integer multipliers are 0–250 and affect only prediction-time scores; changing them never requires reindexing or advances `indexRevision`. Zero removes the order’s virtual contribution. Extending the valid range to 0–250 needs no new schema migration and preserves existing chosen values; the default stays 1×. Older executables refuse schema 5 instead of downgrading it.

## Storage model

| Table | Representative fields | Purpose |
| --- | --- | --- |
| `sources` | `id`, `kind` (`imported`/`personal`), `display_name`, `enabled`, `revision`, `content_hash`, `index_max_n`, timestamps | Independently managed corpus membership |
| `imported_files` | `source_id`, `original_path` | Main-only original location for explicit availability checks; cascades on source deletion |
| `documents` | `id`, `source_id`, `body_text`, `byte_length` | Retained imported UTF-8 text for per-source reindexing |
| `personal_documents` | `id`, `source_id`, `body_text`, `byte_length`, nullable `learned_hash` | Explicitly saved personal text, independent of whether any counts are learned |
| `ngrams` | `source_id`, `n`, `context_key`, `next_token`, `frequency` | Counts by source and N=1–7 |
| `settings` | `key`, JSON `value` | Source mode, maximum N, pool/preview/acceptance bounds, seven virtual multipliers, consent and index revision |

The schema is defined in `src/main/storage/store.ts`. Imported retained copies remain in `documents`. Personal notes use a separate UUID and unique source reference with cascading deletion; their source has `kind='personal'` and no filesystem origin. Source metadata keeps the saved name, revision, content hash, enabled flag and timestamps. Personal `token_count` is zero when unlearned; `learned_hash` is null or identifies the saved content explicitly learned. Bodies are not duplicated in the import table. N-grams keep the first observed display spelling. Initial settings remain `personalLearning=false`, `sourceMode="imported"`, `maxN=3`, `poolSize=10`, `previewWords=3`, `acceptWords=2`, `ngramScales=[1,1,1,1,1,1,1]`, and `indexRevision=0`. Prediction settings writes cannot change consent; the separate `documents:learning` call requires a boolean.

The N-gram primary key `(source_id, n, context_key, next_token)` supports per-source context/prefix ranges. An additional `(n, next_token COLLATE BINARY, source_id)` index supports prefix-first lookups. All text values use bound SQL parameters. List responses contain at most 100 summaries, never stored bodies or the full index.

## Import lifecycle

1. User selects a `.txt` or `.md` file using an OS file dialog. Only UTF-8 text is accepted; reject unsupported encoding/over-limit files with a clear error. Bound cumulative import size and file count.
2. Assign a stable source identity, store its text locally and tokenize into sentences and word sequences. Build **N=1–7** counts without crossing sentence/document boundaries.
3. Write the new source text, revision and counts **in one transaction**; the previous revision is replaced rather than double-counted. A repeat import of unchanged content is a no-op or idempotent replacement.
4. The user can enable, disable, delete or reindex that source independently. Disabled/deleted source counts must not affect predictions; no full-corpus rebuild is required.

TND-002 exposes import, list, reindex and delete in **Sources**; TND-004 adds the **Use** checkbox. Toggling changes only that source's enabled flag and global `indexRevision`, preserving all text, counts and source content revisions. Repeating the same flag is a no-op. Replacement preserves the stored flag. Each selected canonical path gets a stable UUID (Windows path identity is case-folded); renaming/moving a file creates another identity. Identical contents at different selected paths remain independent. A leading UTF-8 BOM is removed during decoding. Import cleanup maps FF (U+000C), VT (U+000B), NEL (U+0085), LINE SEPARATOR (U+2028) and PARAGRAPH SEPARATOR (U+2029) to LF, and all other Unicode control characters (`Cc`, C0/C1 including NUL/DEL) except TAB/CR/LF to spaces. This avoids concatenating words and prevents N-grams crossing page/line boundaries. Ordinary spelling, tabs/CR/LF and Unicode format marks are retained. The selected file is never rewritten; the local retained copy and content hash use the cleaned text. Reimport of the same content and current index format is a no-op; replacement and explicit reindex increment revisions and `indexRevision`.

Reindex reads the stored body and needs no access to the original file. Deleting a source cascades to its body and counts, leaving other sources intact. A mixed selection reports per-file failures and keeps valid imports; a selection exceeding batch count/byte limits is rejected before any contribution is written. No external path is accepted from the renderer. Permission, missing-file, encoding, size and DB errors are recoverable and do not expose internal paths in UI errors.

Sources opening / **Check files** invokes a separate validated, no-argument IPC request. Only remembered import paths are checked with asynchronous stat/read-only-open checks (no body reads), bounded to 1.5 seconds per request path; no file body or directory is scanned, no background watcher runs, and prediction/startup metadata reads do not trigger filesystem checks. Missing file/parent and denied access are distinguished from unknown errors/timeouts; unknown locations do not authorize the conditional action. **Clear index** is shown only for missing/unavailable originals with existing N-gram rows. Its UUID-only IPC rechecks that condition under the source mutation lock before the existing transactional delete; this removes retained text, all counts and location metadata, and invalidates predictions. Ordinary Delete and retained-copy Reindex remain available. A restored file prevents conditional cleanup.

Older imports have no recoverable path because previous versions stored only its hash. Migration preserves them with unknown availability; ordinary Delete still works, and an explicit reimport backfills the authorized path; current-format identical reimports keep revisions, while old-format contributions rebuild to N=7. Paths are not guessed from names and no disk scan attempts recovery. Older schema-1/2/3/4 executables refuse the schema-5 database; no downgrade is performed.

## Import bounds and token rules

- Only explicitly selected regular `.txt` / `.md` files, with case-insensitive extensions and fatal UTF-8 decoding. Reject control/format characters in names; clean body controls as described above rather than rejecting the whole file. Invalid UTF-8 and UTF-16 BOMs are still rejected; no encoding conversion is attempted. Reject symbolic links, linked parent folders, directories and traversal-style paths; never scan a directory.
- At most **10 files**, **5 MiB per imported file**, **10 MiB per selection**, **100 combined imported sources/personal documents**, **32 MiB total stored UTF-8 text**, **500,000 tokens per indexed text**, and **128 Unicode code points per indexed word**. Personal saved texts retain a separate **1 MiB** limit. File/selection byte limits count original bytes before cleanup; stored-text limits count the cleaned UTF-8 body. Bounded reads also detect overgrowth/changed metadata during import. The worker streams tokens and flushes a Map at 4,096 distinct rows or 4,096 words, retaining only six context tokens. Batched UPSERTs add within that replacement transaction; JavaScript never holds the complete all-N index. Progress is main-owned bounded numeric metadata polled through `sources:progress`. Failure or worker interruption rolls back source text, counts and revisions together. Other connections retain the old committed index until replacement succeeds.
- Token keys use Unicode NFC and locale-independent lowercase. Letters/numbers with combining marks form words; internal straight/curly apostrophes belong to a word and normalize to a straight apostrophe in the key. Accents are preserved, with the first original NFC spelling retained for display. Non-word Unicode format marks (including zero-width and bidirectional marks, soft hyphens and embedded BOMs), unusual spaces and symbols are accepted and separate words; they contribute no word tokens. No blanket removal of joiners or formatting is applied to the stored body.
- `. ! ? 。 ！ ？ ; :`, CR and LF end a context. Other punctuation (including commas/hyphens) separates words. Contexts are reset at every sentence/line/document boundary. This conservative rule intentionally does not infer abbreviations or perform language-specific segmentation. CJK runs are kept as written, without morphological tokenization.
- N=1 uses the empty context string. N=2–7 use JSON arrays of the previous one through six normalized tokens. All seven orders are indexed independently of the slider. Prediction combines every usable order through the selected maximum using the [two-stage pool](prediction-pool.md).

## Personal writing

TND-005 implements local New/Save/Open/Delete. Save accepts exactly an opaque ID/null, expected revision/null, name and text; names have 1–120 code points with no control/format characters, bodies are well-formed Unicode plain text (tab/CR/LF allowed) with a 1 MiB UTF-8 limit. Both imports and notes share the 100-item/32 MiB budgets. Lists contain at most 100 summaries without bodies; Open returns one explicitly selected body. No renderer path or arbitrary SQL is accepted. Saved text preserves Unicode spelling and line endings.

**Learn from my writing** starts off, independently of Save. Enabling never bulk-indexes existing notes. An enabled Save tokenizes only that saved snapshot and commits saved body, source/hash/revision, replacement counts and `indexRevision` together. Unchanged re-saves are no-ops when the learning state already matches, so frequencies/revisions/cache identity remain stable. A failed index/write rolls the whole operation back; the UI retains the unsaved text. Stale expected revisions are rejected rather than overwriting newer saves. Notes with words/token counts over indexing limits can be saved with learning off, within storage limits.

Turning learning off retains existing counts but excludes all personal sources from prediction queries immediately. Saving a note while off clears that note's old counts and `learned_hash`, so re-enabling cannot revive an older version of that saved note. Per-note **Use** flags survive saves; source mode, consent and these flags all gate personal predictions. Source/consent/count changes advance `indexRevision` and refresh the renderer's request generation; imports remain independently selectable.

**Remove learning** clears one note's counts while retaining the saved body and activation flag; a later enabled Save can learn it again. **Reset personal learned data** transactionally clears all personal counts/hashes and turns learning off, preserving notes and imported sources/counts/preferences. **Delete** removes one personal source and cascades to its document/counts. No full-corpus rebuild or per-keystroke persistence occurs.

## SQLite queries and indexing

A composite index should support fast lookups by active `source_id`, `n`, context and candidate. Prefix lookup must use a normalized token prefix and a SQLite-index-friendly query where possible; test accented Unicode and case folding explicitly. Keep a small bounded LRU for repeated lookups, keyed by source selection, enabled N, text prefix/context and current source revisions.

The repository enforces requested IDs plus `enabled=1` at every order; the worker resolves those IDs from source mode and consent. SQLite uses the primary key for source/N/context equality and binary prefix ranges, sums across files and applies a bound `LIMIT X` separately per N. The worker merges at most 7X records, scales admitted counts by their configured N multiplier, merges equal words and takes final top X before sampling. One sequence shares a read snapshot, with at most 7×10 candidate queries. Result bounds do not cap SQLite scan cost, derived DB/WAL size or latency. See [prediction rules](prediction-engine.md) and measured limits in verification.

**Never preload the entire database into renderer memory.** Indexing or expensive scanning runs off the renderer event loop; the UI stays responsive.

## Privacy and deletion

Imported and personal text remain **on the current machine** in the application's data directory. Deleting a source removes its stored text and index contribution. Uninstalling an application does not always remove OS user data automatically: document where that folder is and include a reset command/UI action in the finished release.

## Database size in Settings

Settings shows measured file lengths for **Database**, **WAL** and **SHM**, plus their total, formatted in B/KiB/MiB/GiB with exact byte counts in the tooltip. It refreshes when the panel opens, after completed settings/source/document operations while open, or with **Refresh size**. This is a measurement at request time, not a continuous disk monitor. The local worker asynchronously stats only `typenudge.sqlite3` and its two fixed sidecars; renderer cannot supply a path or request a directory scan. Missing sidecars count as zero; missing/inaccessible database files produce a recoverable error rather than a misleading zero.

The total includes retained text, N-gram indices, SQLite overhead and current sidecar file lengths, not other app files or OS allocated-block accounting. It is separate from the **32 MiB retained UTF-8 text quota**, which does not bound derived database size. Reading the size never runs VACUUM, checkpoints the WAL or changes frequencies. Deletion frees records for SQLite reuse; file lengths can remain unchanged until normal SQLite maintenance, so deleting a source need not immediately shrink this display.
